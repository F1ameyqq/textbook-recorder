# 暂停、回读与恢复

保存超时不能证明保存失败。平台可能已收到请求，而程序没有取得回执；此时重复新增会产生重复题。保留原题单、进度、锁、意图记录和日志，先核对当前失败任务。

连续无保存请求证明只能来自 fresh append 创建的原始活意图及未中断的页面、连接和请求观察。加载磁盘意图不会重建该资格；磁盘计数为零、回读缺失、请求失败或非 2xx 响应均不能单独解除未知保存锁。新版恢复会保留匹配活意图的最高计数和已知回执，但不能为旧服务已经丢失的历史观察补证。

## 正常暂停和关闭

暂停请求让执行器在安全边界停止，不撤销已经发送的保存，也不是立即断开连接。请求暂停后查看 `recorder:status`，等待任务确认终止。仍有 `pending` 或运行中的任务时不要关闭进程、重开客户端或手工编辑页面。

```powershell
npm run recorder:pause
npm run recorder:status
```

关闭服务只断开程序连接，保留用户页面和登录。关闭可能拒绝尚未确认终止的任务；先处理暂停和状态，不强行删除锁文件。

```powershell
npm run recorder:stop
```

## 先判断状态

| 状态或现象 | 下一步 |
| --- | --- |
| 达到 limit 或正常暂停后的 stopped | 确认任务终止、无错误、无写入锁及已处理题目回读通过，再用同一题单和 state 接续 |
| 尚未开始写入，题单校验失败 | 本地处理审校问题，再校验；不改历史证据 |
| 任务仍运行或控制请求超时 | 查看同一服务的状态，不再次提交执行命令 |
| 有成功回执，刷新回读失败 | 只读检查回执中的同一记录，不重新新增 |
| 请求已发出，回执缺失或结果未知 | 保持写入锁，读取失败任务的实际目录和记录 |
| 已有内容与题单不同 | 停止并交负责人判断，本版不自动覆盖 |
| 题目已完整存在且与题单相同 | 核对身份及来源后跳过，不重复写入 |

## 回读与核对

若原单题 execute 仅在 `source-pages` 阶段失败，且原终止报告明确没有保存意图，不能把通用写入锁当作已经新增，也不能直接删除锁。可在原 manifest/state/taskId 的 reconcile 参数中绑定 `preAppendFailureCommandId` 与失败前导出完整原目录的 `baselineProbeCommandId`，使用来源页提前失败核对。程序核对原失败命令、已审题单哈希和失败前基线，再刷新确认目标题缺失、全部原记录及来源逐字节一致，记录“尚未创建草稿或开始插入”证明；它不会冒充同连接无保存请求观察或生成保存回执。该通路只适用于原单题来源页失败，没有原基线、有保存意图、已保存回执、未知编辑或新增后的失败时均拒绝。

若原单题 execute 在 `answer-native-paste-readback` 阶段失败，题干插入尚未开始，可另用 `preStemFailureCommandId`、同一失败前 `baselineProbeCommandId` 和原 `pendingPath` 核对答案草稿。该通路要求原终止报告与原意图逐项相符、已审题单哈希不变、原意图无保存回执且实际记录的保存请求为零；刷新后目标题必须缺失，全部原记录、身份、来源及内容逐字节保持一致。证明明确标记“题干插入尚未开始”，不会标记为未创建草稿，也不会把磁盘证据冒充连续连接观察。题干插入或保存阶段的失败、观察到保存请求、缺少原意图或原目录基线、任一记录改变时均拒绝解锁。两种提前失败参数互斥；使用核对命令生成证据和恢复原进度，不手工清锁或修改进度。

`verify` 对题单做只读核对；单题 `readback` 用于定位失败任务，`reconcile` 绑定原题单、原进度和该任务的保存意图，检查实际服务器记录。恢复只能核对当前失败范围，不能借另一份题单解除写入锁。

先在本地创建 `data/jobs/readback-args.json`，字段来自当前失败任务，不套用其他题的标识：

```json
{
  "manifest": "data/jobs/batch.json",
  "state": "data/jobs/progress.json",
  "taskId": "替换为原题单中失败任务的id",
  "capture": true
}
```

```powershell
npm run recorder:readback -- data/jobs/readback-args.json
```

准备 `data/jobs/recovery-args.json` 时保留相同的 `manifest`、`state`、`taskId`，去掉 `capture`，把 `pendingPath` 设为该失败任务原检查点中记录的保存意图文件。它不是新生成的意图，也不能指向其他失败任务。

```powershell
npm run recorder:recover -- data/jobs/recovery-args.json
npm run recorder:status
```

命令接受本地 JSON 参数文件，不接受任意浏览器脚本。恢复结果需等状态确认终止后判断；命令已受理不代表解锁成功。

恢复时需要完整目录记录与真实刷新回读，核对书号、章、节、题序、服务器身份、全文、来源和图片。已有记录数量或界面中的一段文字不足以证明未保存；缓存列表也不等于刷新后的服务器证据。

只有恢复证明明确确认同一记录已保存、完整内容一致且此前记录保持不变，才能记为已保存继续。工具无法确定时保持未知和写入锁，交负责人处理。不要手改 `attempts`、补造收据、把 `unknown` 改成 `not_saved`，也不要通过删除进度、令牌或锁来重试。

零保存请求的证明还需同一连接的实际观察及完整刷新基线。单凭磁盘意图写着零次或列表中未找到记录，不能解锁。本版恢复无法出具充分证明时可能持续保持锁；这不表示可以绕过锁重试。

## 恢复前保留材料

保留失败时的原题单和素材、进度、任务标识、时间、意图与回执、刷新回读和目录快照。修改审校内容应另存版本；冻结题单或资产变化会使旧进度失去对应关系，不能直接沿用执行。

请只把脱敏后的错误类型、软件版本和阶段说明交给维护者。原书图片、原始 HTML、账号、令牌、控制密钥及完整本地证据不要上传共享仓库。私有 GitHub 仓库仍属于另一份副本。

## 已明确授权的空答案和来源归零修复

已有题答案为空且正文、答案来源均为0时，先读取完整目录并保留原记录ID。只有用户明确要求补回答案、来源和指定格式后，才生成单题修订；依据原书核对答案及来源页，不能自行解答。

mapping 的 `correction.beforeManifest` 和 `beforeSha256` 仍绑定已审原题单；可另加 `beforeSnapshot: {path, sha256}` 绑定同一 job 内的完整服务器目录快照。快照须为 `reviewed-empty-answer-source-repair-baseline`，含书号、目标原ID、目录 nodeID、全部 records 以及 `authorization: {source: "direct-user", userQuote: "用户本次明确要求"}`。该字段仅支持单题、空答案、两来源归零的记录，不代表允许覆盖其他变化。

写入前刷新确认完整目录与冻结快照完全相同；来源恢复使用当前书籍原图列表中的真实地址和已审页码，不能只切换预览。每次保存都核对回执，最终要求答案非空、来源准确、原ID不变、全文及原生格式通过回读、其他题完整内容不变。未知保存及写入锁仍按上文处理，不能用新快照解除。

平台页码输入可能只切换原图，不修改既有题的来源字段。遇到该情况，先刷新核对原记录；不能把预览页码当成保存来源。本版的 `complete-record-repair` 仅用于原已授权、目录末题、空答案且两来源归零的单题修订：沿用原 manifest/state/taskId/pendingPath 和原冻结快照，确认完整服务器目录仍与原快照完全一致后，通过固定保存接口向原ID提交已审最终题干、官方答案和正整数来源。它不重放失败的界面请求、不创建新题；补全意图以独占文件登记，至多一次请求，未知响应不能再次提交。只有真实成功回执、刷新全文及其他题不变的证明均通过，才完成原进度并解锁；原失败意图保留。若记录已完整符合原已审最终题单，则只读验收。

新的已审 `beforeSnapshot` 修订由普通 execute 自动走同一受限补全路径。固定保存接口按当前平台客户端契约发送 JSON，并同时提供 `mainPicURL`、`answerPicURL` 和对应页码；原图地址从当前书号的 `detail/basicinfo` 与对应上传的 `file/progress` 读取。明确收到 HTTP 200、业务 errno 300001“参数错误”且无保存ID的旧补全，只有原命令结果、题单哈希、实际响应日志和刷新后完整原快照均绑定核对后，才可通过 `priorCompletionCommandId` 修正参数；旧意图和回执保留。其他响应或缺失回执仍视为未知，禁止新请求。

## 不在本版内的恢复

本版提供受约束的追加、已审原ID修订与结果核对，不提供批量删除、重建、任意 HTML 修复或未知保存后的自动重试。需要更改已有题目、重新分题或处理来源错误时，须有对应的明确用户授权和绑定基线，不能把一次普通执行授权扩大为这些操作。

换书应使用新的独立工作目录，保留旧目录中的会话与证据。书号不匹配是保护检查，不能通过删旧状态或改成另一书号来解除。
