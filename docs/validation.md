# v0.3 验证边界

这版包含仓库 skill 和采集、OCR、裁图、配对、待审草稿、哈希绑定批准、追加执行、回读及恢复接口。文本分题和答案配对仍由实际读原图的 agent 判断。

本机 Windows 的离线回归：Node 309 项，307 通过、2 项因文件符号链接权限跳过；Python 9 项全部通过。Windows 目录 junction 的越界和项目根别名另有实际测试，不依赖这两项跳过。GitHub CI 对 Windows/Ubuntu 和 Node 22/24 执行相同代码回归及 Python 裁图检查；不下载 OCR 模型或访问录入平台。

独立 agent 从三页合成原图及明确标记的 OCR 草稿开始，实际查看原图与裁图，执行裁图、配对、草稿、离线预览检查、批准及批准后复检。覆盖带配图选择题、无编号知识建构、跨页整体活动及无需作答的流程排除。首次因跨页候选 ID 重复被拒绝；补充契约说明后修正输入重跑，三道完整任务获得 approved，最终 `valid=true`、`readyForExecution=true`、零错误。首轮材料原样保留，第二轮使用新文件名。测试使用 `source=fixture`，不会进入平台执行。

这些结果证明本地工具接口可以串联，以及指定的结构/来源/批准守卫起作用。它们不证明真实教材语义必然正确，不证明实际 OCR 模型在新电脑上运行，也不证明新平台采集和保存已验收。

上线时需在用户授权的新书上完成：连接原登录会话、空编辑器采集少量正文与答案页、实际本地 OCR（若使用）、逐原图审校、单题真实保存回执与刷新回读，再按同一状态接续小批次。图片加载时序、扩展拦截及平台业务错误需要真实通路证据。复杂上下分式、加点字等未支持的原生排版保持待处理，不能靠线性文字或整题截图绕过。

采集续跑校验的是已下载缓存的本地哈希，不能证明同书号的线上原书没有更新。来源变化时保留旧作业，新建获授权的采集作业并重新审校。

## 2026-10-09 连接复用与状态输出优化

新增后台服务启动或复用、controller 默认摘要与本地等待，以及已批准题单在正常 limit 边界的可选自动接续。连接失败有重连上限；原任务、题单字节、资产身份和进度 ID 变化、暂停、不进展或未知保存都会停止接续，不重发原命令。服务端检查实际连接、上一终止命令和暂停版本，覆盖终止后暂停及检查与提交之间暂停。暂停先持久化，断线、重启和只读命令不会解除；普通执行按请求入口的同版本证明恢复，迟到回应不能清掉新的暂停。仅通过同一活连接、随机 Page 标记、书籍身份和空编辑器检查的自建页可以在正常关闭时清理；用户原有页、历史页和非空编辑器保留。

本机 Node 全量回归 473 项：471 通过、零失败，2 项因 Windows 文件符号链接权限跳过。新增测试覆盖同连接多命令、标签归属与手动输入保护、连接上限、单次提交与等待超时、正常接续及各类阻断、暂停持久化和竞态、跨连接派发拒绝、旧服务协议拒绝和丢失接受证明时保留写入锁，以及替换服务后的同一新进程健康检查；共享内容扫描和 Git whitespace 检查通过。
