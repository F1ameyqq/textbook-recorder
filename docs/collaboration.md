# 多人协作

先由负责人分配书籍和目录，再各自安装、配置账号和扩展令牌。每人使用自己的本地配置、题单、素材、进度与证据；DPAPI 令牌不能随仓库迁移。

一书一份独立工作目录。接另一书时从新仓库副本配置，旧会话及证据保留；不能只在旧目录改 `bookId` 或删除会话文件换书。

## 分配范围

不同朋友负责不同书籍，或由负责人明确划分同一本书中不重叠的章、节。**同一节只能有一位写入者。** 本地进程锁只保护一台电脑，不能阻止另一台电脑同时新增。不要让两人按相同起点准备并执行。

分工表至少记录书籍、章、节、负责人、实际已有记录数、本轮起点和状态。准备者依据原书确定题目边界和来源，复核者检查覆盖及全文，写入者核对平台基线后执行。一个人承担多项角色时也要分别完成这些检查。

## 冻结与执行

审校通过后冻结题单及图片，记录本地摘要和明确起止范围。执行期间不改题单、不换图片、不手动调整同一目录，不同时启动第二个浏览器客户端。

执行器按已批准题单运行，过程中不调用模型。题目拆分、答案判断和困难排版仍需审校；朋友更换电脑或书籍后，应先离线演练、只读核对及单题试录，不能继承别人的生产验收结论。

达到批次上限的正常 `stopped` 不代表录入失败。`execute --continue` 仅在明确的 limit 边界、无错误及无未知保存且实际进度增加时，用同一冻结题单和进度接续；pause 或异常停止，不为下批复制空进度。`recorder:verify` 未指定 `--limit` 时核对整份题单（最多 1000 条）；显式设置较小上限时，只能报告这部分核对结果。

## 交接

交接前暂停并等待当前任务终止，再关闭自己的服务。交接给下一位时提供：

- 分配范围、冻结题单版本及素材摘要。
- 实际平台目录与最后核对的记录，下一条应接续的位置。
- 原进度及回读证据，哪些任务完成、跳过或仍有问题。
- 任何未知保存结果及写入锁；未知未解决时不得移交为“可以继续”。

接手者取得当前平台的只读基线并核对原书，不直接把交接说明当作最新服务器状态。保持原历史证据，避免通过重新编号或换题单名字掩盖失败任务。

## 共享仓库边界

GitHub 用于共享程序、文档、测试和合成样例。不要提交本地 `config/recorder.json`、令牌、控制凭据、真实题单、原书内容、裁图、服务器记录或执行日志。发起问题报告时提供脱敏后的版本、命令类别、失败阶段和可复现的合成输入。

合成 `fixture` 样例只能用于离线演练与学习结构，不能改成 `production` 提交平台。共享 CI 只覆盖纯本地测试、演练和扫描，依赖旧生产材料的浏览器及公式场景没有纳入。

只把离线测试称为离线测试。跨电脑安装、新书适配和实际保存需有各自的证据；不以 CI 通过、演练通过或某一次成功保存宣称无人值守整本录入已验收。
