## 共享内容

- `workflow:prepare` 统一编排本地准备、哈希绑定与待审材料。
- `workflow:patch` 局部修改准备材料，保留旧版本并使旧审校声明失效。
- `workflow:incident` 输出有限、脱敏的异常摘要。
- `workflow:ocr` 默认 GPU 0，校验实际执行设备，不静默退回 CPU；CPU 仍可显式选择。OCR Python 可由环境变量或本地配置指定。
- 参数化的 OCR / 公式实验运行器、评分工具和合成测试，见 [实验工具](ocr-benchmarks.md)。
- 已选择的 DeepSeek Flash MAX 配置与冻结 v2 提示词，见 [配置说明](ocr-correction/README.md)。这是参考材料，云端纠错尚未接入通用 CLI。
- 共享扫描兼容 Git worktree 的 `.git` 指针文件；该文件仍禁止进入发布文件清单。

原书内容、图像、真值、云端响应、凭据、模型缓存、本地配置和运行证据不随 Git 推送。两份依赖本机固定路径或旧实验目录的一次性脚本保留在本地，未纳入共享版本。

## 验证

- `node --test --test-concurrency=1 tests/*.test.mjs`：1,546 项，1,543 通过、0 失败、3 跳过，约 337 秒。3 项跳过分别为缺失本地书籍夹具、两项 Windows 文件符号链接权限限制；目录 junction 拒绝路径另有覆盖。串行运行，仅使用合成数据、独立测试浏览器或本机伪服务，不连接真实录入平台。
- `python -B -m unittest discover -s tests/python -v`：17 项全部通过；OCR 初始化与输出用模拟对象验证，没有加载识别模型。
- `npm run demo`：4 道合成任务通过，重复追加 0，平台请求 0，模型调用 0。
- `npm run check:share`：共享扫描通过；正文、图像、运行状态和凭据继续排除。
- `git diff --cached --check`：通过。
- MAX 参考配置 JSON 可解析，提示词 SHA-256 与冻结实验逐字节相同；原实验冻结的 60 个文件哈希未变。
- 新增准备接口与最新主干调用契约已做独立静态复核，未发现重要兼容性阻断。

测试由 Windows / Node.js 24 和已有 Python 环境执行；跨系统 CI 结果应另行查看，不把本机结果当作所有电脑验收。

## 结果边界

这些检查证明本地软件、拒绝路径和合成场景。OCR 质量及 MAX 纠错的历史实测另见 [50 题结果摘要](ocr-correction-results.md)：32/50 提升至 44/50 是同样本调优结果，仍需验证新样本。发布整理没有额外发起模型请求或 GPU 识别，也不等于新书平台验收、整书完成或自动切换任务版本。
